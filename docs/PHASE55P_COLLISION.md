# Phase55-P 충돌 2건 진단

두 건의 주 원인은 **(c) 예측–실제 차이**다. EC 제동꼬리는 끝점 도달 후 `stop_command`를 정지까지 계속 적용한다고 가정하지만, 실제 실행기는 끝점 허용 범위를 감속 중 벗어나자 같은 경로에서 `ENDPOINT → NORMAL`로 바뀌어 재가속했다. 두 접촉면은 마지막 검사 지도에 이미 점유로 기록돼 있었다. 마지막 U-Graph 설치 이후 새 경로 설치는 없었다. 시뮬레이션·solver·EC rollout·SDF 재계산 없이 저장 로그만 대조했으며, 방법·수치·결과는 변경하지 않았다.

여기서 접촉은 로그의 기하 평가 시점이다(PhysX 접촉 이벤트가 아님). D075는 상단 벽 footprint 침범이고 정적 상자 overlap은 없다. D150은 Slalom3와의 overlap이다. D150의 저장된 최초 접촉 bracket은 약 68.247842s이며 72Hz 검출은 68.250000s다.

## 읽기 범위와 값 정의

- 대상은 `phase55p_01/main/SLW_D075_221_U-GRAPH/attempt1`과 `SLW_D150_222_U-GRAPH/attempt1`뿐이다.
- 실제 여유는 `clearance.jsonl`의 저장된 72Hz 구간 최소값 `min(lower_m, corridor_lower_m)`이다. Graph node 여유와 EC 예측 여유는 각각 `ugraph.jsonl`, `exec_cert.jsonl`에 기록된 값이며 다시 계산하지 않았다.
- 접촉면 셀은 아래 명시한 표면점에 가장 가까운 저장 grid 중심이다(`rint((q-origin)/h)`, h=0.01m). snapshot의 `occupied/observed` 배열만 읽었다. `values` 복원·EDT 계산·새 지도 생성은 하지 않았다. 점유 우선, 그 외 observed이면 빈 칸, 아니면 미관측으로 구분했다.
- 72Hz 타임라인의 각 행은 `(t−1/72,t]` 구간이다. 해당 tick의 적분이 제어 명령 갱신보다 먼저이므로, 엄격히 이전 제어 tick의 명령·설치 경로를 연결했다. 각 run 216개 구간(3초)을 빠짐없이 수록했다.
- U-Graph의 `minimum_node_clearance_m`은 Graph 속도 궤적의 node 제약값이다. 실제 실행은 PP+SP이므로 해당 값이 실제 궤적 여유라는 뜻은 아니다.

## SLW_D075_221_U-GRAPH

접촉면 좌표는 (3.020700, 0.900000)m이다(최종 중심의 x와 상단 벽 내면 y=0.9를 이은 법선의 표면점). 접촉 전 3초의 EC 58건에서 이 셀은 전부 **점유**였다. 따라서 (b) 지도 미관측으로 분류하지 않는다.

마지막 설치는 38.444444s, U sequence 107 / chunk 35이며 길이는 **0.018573m**다. EC #110는 38.555556s에 끝점 제동을 시작해 38.888889s에 v=ω=0이 된다고 기록했고, 최소 여유 0.109191m로 PASS했다. 실제로는 38.555556s `ENDPOINT` 다음 38.666667s에 **새 설치 없이 NORMAL로 재가속**했다. 예측 정지 시각의 실제 직전 구간 속도는 0.244507m/s, 실제 여유는 0.079779m였다.

최근 3초의 U 재설치 간격은 0.111111~0.444444s(표의 첫 설치는 직전 구간 설치와의 간격 포함)다. 마지막 설치 후 접촉까지 0.958333s 동안 **U/CUT 추가 설치는 없다**. 실패한 재풀이들은 아래 표처럼 기존 경로를 교체하지 않았다. 그러므로 (d) 접촉 직전 재설치가 곧바로 충돌을 만든 사례로 단정할 근거는 없다. 짧은 해 설치가 끝점에 빨리 도달하는 계기는 되었지만, 직접 관찰된 불일치는 끝점 이후 재가속이다.

채택 solver는 정상 수렴했고 최대 hard 위반 6.781e-18, 최소 node 여유 0.131663m(0.025m 하한 대비 +0.106663m)다. 이 값은 저장 해의 제약 요약이지 새로운 경로 평가가 아니다.

## 분류 근거와 한계

| 분류 | 판단 | 근거 |
| --- | --- | --- |
| (a) 검사 사이 미검사 명령 | 부수적으로 존재 | 끝점 이후 재가속 NORMAL 명령은 마지막 PASS가 전제한 지속 제동과 다르다. 다만 제동꼬리 자체가 없었던 것은 아니므로 주 분류는(c). |
| (b) 지도 미관측 | 해당 근거 없음 | 두 접촉면 셀 모두 접촉 전3초의 모든 관련 EC 지도에서 occupied. |
| (c) 예측–실제 차이 | 두 건 모두 주 원인 | EC는 ENDPOINT 이후 제동을 고정하지만 live는 completed를 영속 정지 상태로 저장하지 않아 허용 범위를 벗어나면 같은 XY 경로로 재가속. |
| (d) 재설치 시점 문제 | 주 원인으로 채택하지 않음 | 접촉 직전 새 설치 없음. 마지막 설치 이후 ENDPOINT→NORMAL 사이에도 동일 sequence/chunk/path. 짧은 경로 설치는 관찰된 상황이나 재설치만의 인과 효과는 이 로그로 분리 불가. |
| (e) 기타 | 채택하지 않음 | 관측된 명령 전환과 저장 EC 종료 시각으로 두 사례가 설명됨. |

EC 재검사와 STOP_WAIT 전환은 로그에 남아 있다. D075는 38.944444s 재검사 REJECT → 39.000000s STOP_WAIT → 39.402778s 벽 침범, D150은 68.166667s REJECT → 68.222222s STOP_WAIT → 68.250000s 상자 접촉이다. 늦은 감속은 진행 중인 이동을 즉시 제거하지 못했다. **같은 안전 모델의 새로운 재판정이나 가상 수정 효과는 계산하지 않았다.**

정적 코드 대조: [EC braking-tail](../research/nomad_phase52ec/rollout.py)은 `braking=True` 이후 `stop_command`를 반복한다. [SPAlignment.control](../research/nomad_phase20/execution.py)은 `endpoint_stop`이면 그 호출에서만 `completed=True`를 반환하고 영속 ENDPOINT 모드를 설정하지 않는다. [실제 Execution.apply](../research/nomad_phase20/runtime.py)는 매 제어 tick 다시 `sp.control`을 호출한다. [Phase55 runtime](../research/nomad_phase55p/runtime.py)은 U-Graph XY를 이 실행기에 설치한다. 코드는 조사만 했고 수정하지 않았다.
